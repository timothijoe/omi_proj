本入口读取已保存的 `periodic_episodes/`，不连接 ROS、不启动机器人、不修改训练数据。适用于检查每个回合的原始周期，包括没能进入训练池的周期；与已有只显示有效示范的工具不同。

从项目根目录启动当前会话：

```bash
cd /home/zhoutong/omi_folder/omi_proj
bash scripts/view_rl_episodes.sh \
  --run local/rl_training/bc_demo_new_20261007_213643_rl_live_01
```

终端打印 `READ ONLY: http://127.0.0.1:8765/`，在**本机浏览器**打开这个地址。端口被占用时加 `--port 8766` 并打开对应地址。`Ctrl+C` 只关闭查看器。服务仅监听本机回环地址；页面按需读取单个周期文件，不会一次将整个 20 GiB 会话加载进内存。若脚本运行在远程主机，需由操作者另行设置端口转发，本入口不会对局域网开放。

## 页面怎么看

- 回合下拉框包含所有 `periodic_episodes` 目录。`audit.json` 存在的是完整审计回合；仅有 `staging.json` 的中断记录也会出现，并标为“仅暂存”。这两类不能混算为完整回合。
- 顶部显示本回合周期数、可训练 transition 数、成功/结束标签及 `excluded` 原因。滑块或键盘左右键逐周期查看；“播放”顺序翻页。原始周期从 0 编号，首段历史不完整时可能没有图像。
- 每个周期显示外部 RGB 与腕部 ROI 的 **10 帧历史**；可选历史槽位 0–9，9 是最新帧。下方同时放大所选两路图像，并显示 A/B deformation、shear 向量以及 depth 数值场。黄色框是当前历史槽位。标成 `MISSING` 的图像须结合 `history_mask`、`camera_mask` 和回合审计判断。
- 文本列出动作来源、gate、模型版本、归一化动作、发往接收端的 wire 动作、观测时间与发送相位、EEF 位置及回执配对状态。`训练片段=是` 来自对应 `ready.json` 片段的周期范围；`Learner导入=是` 还要求有 `imported.json`。两者不同，也都不证明末端实测完成命令。

建议逐个回合从开始翻到结束：检查两路画面是否卡住、错位或突然消失；接触前后视觉和触觉变化是否合理；人工接管与策略来源是否符合现场操作；成功标记、有效片段和排除区间是否符合实际。对于可疑周期，记下回合 ID 与周期号，再查该目录的 `audit.json`、`pairing.json`、`receipts.jsonl` 和 `NNNNNN.npz`。**人工看图不能单独证明时间因果、物理动作完成或任务成功**；以审计与真实现场记录共同判断。

当前 `rl_live_01` 有 10 个完整回合、1959 个周期，另有 1 个中断留下的 194 周期暂存目录。完整回合中 1059 条进入训练片段，900 条被排除，其中 766 条是缺少命令后的因果 EEF。查看器保留并展示这些周期，不会把它们重新判为有效。[数量与时序分析](../docs/agent/training/chronicles/2026-10-08-first-online-rl-run.md)。
