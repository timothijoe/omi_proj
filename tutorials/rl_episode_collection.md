## 新一批示范采集（2026-10-07）

当前计划：新采人工数据→审核→训练新BC→用对应示范和新BC初始化双池在线RL。
双池实现、验证结果与待办见[开发交接记录](../docs/agent/training/chronicles/2026-10-07-dual-replay.md)。
现有双池目录仍使用旧8回合，下面的采集不会自动替换其模型或种子。

确认现场安全、传感器及接收端运行，并关闭其他动作发布程序后，由操作者执行：

外部 RGB 来自另一台机器。采集脚本会使用 domain 13 和局域网发现
（`ROS_LOCALHOST_ONLY=0`、`ROS_AUTOMATIC_DISCOVERY_RANGE=SUBNET`），
避免继承终端的 `LOCALHOST` 设置后只能看到本机触觉和 EEF。
接收端建议使用相同的局域网发现配置；修改终端环境不会改变已经运行的节点。
若新采集入口的接收端预检失败，再按[现场启动教程](robot_gamepad_startup.md)重启接收端。

```bash
bash scripts/collect_rl_episodes.sh \
  --output "local/rl_episodes/demo_new_$(date +%Y%m%d_%H%M%S)" \
  --episode-seconds 20 --episodes 10 \
  --control-mode periodic \
  --execute
```

`periodic`按100 ms目标发送，回执与后续观测在回合结束后校验；这是当前推荐的人工作业采集模式。
原同步模式仍可显式选择`--control-mode receipt`，但非零动作的名义完成回执本身约需100 ms，
再串行等待下一步会累计延迟并触发100 ms观测新鲜度门槛。不要通过放宽门槛把不连续数据冒充10 Hz。
周期模式先在`periodic_episodes/`保留全部审计，只有通过动作回执、时间和后续EEF检查的连续片段
才导出到`episodes/`供训练；无效间隔不拼接，按原目录同一模式使用`--resume`。

- 315开始，RB+摇杆人工操作；松开RB为零动作，不运行神经网络。
- 308成功结束；307提前结束或20秒超时，均保留原非成功/截断标签。
- 有效回合默认保留，结束后后台保存；此命令完成10个回合后退出。
- 采集结束按一次Ctrl+C，等待保存和退出；未完成回合仅留审计、不进入训练池。
- 此脚本不启动Learner；周期模式的动作标签是接收端接受的命令，不是实测位移。

每次按315只启动一个回合。终端同时打印 `ACTIVE` 和青色中文开始横幅；
按308成功时打印 `EPISODE_RESULT: SUCCESS` 与绿色中文结果，按307提前结束或到时
分别打印 `MANUAL_STOP` / `TIMEOUT` 与黄色中文结果，异常为红色。每10个周期的
`PERIODIC` 行显示当时 `rb` 与 `nonzero_action`。保存后的摘要区分
`ticks`（周期命令数）、`transitions`（通过校验的有效动作数）和
`nonzero_action_ticks`（全部周期中的非零动作次数），并显示已完成回合数及本次运行累计。
`training_ready=true` 不代表任务成功或动作质量合格，纯零动作回合仍须排查。

进入 `ACTIVE` 后再按315不会重启当前回合。回合结束后的保存阶段按315，新版本会
排队，在保存完成后进入下一回合；如果没有排队，看到 `WAIT_START` 后再松开并按315。
修改后的按键处理只在新进程生效；旧采集进程需先用 Ctrl+C 退出再重启。
2026-10-07现场样例第一回合200个tick中有189条有效动作、105次非零动作，
因为20秒到时而非成功；第二次Start在保存阶段被当时旧进程清除，此问题已做软件修复，
还需在重启后的现场验证。

最近现场出现`receiver rejected/modified command or uses a different frame`。
该通用报错不能直接确认为包络限制；当前按用户要求保留保护设置、暂缓排查。
`keep=false`不用于训练；`keep=true`也需核实实际运动及标签后再作为新BC示范。
本次新数据尚未训练，新BC训练/热启动目录待审核后单独建立。

## 2026-10-07：断点续采与分次采集

不要求采集和训练始终在同一个进程中运行。完整回合先保存为独立文件，训练池是其派生数据。
本次没有启动真机；以下执行命令由操作者确认现场安全后运行。

**续采原目录**：使用原来的配置（含episode-seconds），显式加`--resume`。
不会覆盖旧回合，启动后等315重新开始；不会续发中断前的动作。

```bash
bash scripts/collect_rl_episodes.sh \
  --output local/rl_episodes/collect_20261006_001958 \
  --episode-seconds 15 --resume --execute
```

完整ready/discarded清单是恢复依据，不依赖可能滞后的summary。
上次崩溃遗留、没有ready的staging回合会标记discarded，只保留审计文件，不猜测成功/奖励。
正常Ctrl+C仍先停止，再排空写盘线程；未结束回合不进入训练。

**分次采集、合并训练**：可以使用多个新目录；`--source`后可列出多个路径。
要求观测/动作/奖励/回合契约相同，重复目录/重复episode ID会报错；全局按回合划分训练/留出，
归一化仅统计训练回合。替换下面的session_A/session_B为实际路径。

```bash
bash scripts/train_rl_offline.sh \
  --source local/rl_episodes/session_A local/rl_episodes/session_B \
  --output local/rl_training/shared_serl_v2_01 \
  --updates 100 --batch-size 32 --device cuda
```

新版默认batch256对齐参考配置；以上显式32是十帧输入下显存受限的起步设置，
不等于官方batch256，也不是梯度累积。新版架构详情见[Actor/Learner教程](hil_actor_learner.md)。

**训练中断与恢复**：CLI收到Ctrl+C/SIGTERM后打印STOP_REQUESTED，完成当前更新再保存退出。
模型、目标Q、优化器、温度、随机数状态一并保存。正常续训：

```bash
bash scripts/train_rl_offline.sh \
  --output local/rl_training/shared_serl_v2_01 \
  --updates 100 --batch-size 32 --device cuda --resume
```

这里updates是追加次数。`--resume`使用已有dataset快照和replay，不自动导入之后新增的回合，
也不重新划分验证集；新增数据要新建训练目录，或后续接入在线Learner交接流程。
新架构v2不能resume旧v1训练目录；原始采集文件可以原样再训练。

边界：kill -9、断电不能排空内存队列；训练可能退回上次完整checkpoint（通常每50更新保存）。
中途写坏的dirty replay仍拒绝打开，需要从已完成的episode文件重建；本次未实现自动dirty池恢复。
不要删除原始episodes，也不要手工把clean标志改为true。
恢复采集/训练不意味着恢复机器人位置，物理复位仍由人工完成。

本次网络对齐与中断恢复见[2026-10-07阶段记录](../docs/agent/training/chronicles/2026-10-07-shared-serl-resume.md)；
此前采集实现与现场数据检查见[2026-10-06阶段记录](../docs/agent/training/chronicles/2026-10-06-rl-episode-collection-audit.md)。

## 状态与按钮

`等待开始/人工复位 → 开始键 → 运行 → 成功/超时/手动终止 → 零动作停止 → 后台完成保存、自动保留 → 等待下一次开始`

| 输入 | 行为 |
| --- | --- |
| 开始，键码315（通常Menu） | 启动新回合并重新计时；默认15秒，包含历史预热 |
| 成功，键码308 | 成功结束，最后有效transition的reward=1、terminated=true |
| 到时未成功 | 停止；reward=0、truncated=true，自动保留有效回合 |
| RB，键码311 | 按住才采用摇杆/十字键；松开为零动作，回合继续计时和采集，不运行模型 |
| Back，默认键码314 | 仅在等待开始或后台保存时单按回 home；回位动作不进入训练数据 |
| 不成功结束，键码307 | 结束并标记截断（manual_stop），自动保留有效回合 |
| A/B，键码304/305 | A闭合、B张开夹爪；不需RB；先松开再按触发一次，回合内外均可用 |

按用户指定以315/308/307键码为准，不依赖面板字母；Back 默认键码314，可用 `--home-button-code` 修改。
A/B沿用 `gamepad_test.py` 的夹爪SDK、已知行程标定和默认参数；默认启用，`--no-gripper` 可关闭。
默认连接 `192.168.14.11:55551`，读取 `tutorials/gripper_limits.json`；速度50、力矩上限30%、
闭合位置0、张开位置1000。可用 `--gripper-*` 参数覆盖，与[直接手柄入口](gamepad_control.md#夹爪-sdk-与-a-b-按键)相同。
夹爪命令不属于当前六维机械臂RL动作，也不会作为可回放的夹爪动作写入训练数据。
开始、成功、手动终止采用按下边沿，启动或重连时先松开对应按钮再按；按住不会重复触发。
RB采用按住使能逻辑；成功和手动终止不要求同时按RB。
通过 `--config <配置.json>` 可修改 `start_button`、`success_button`、`stop_button`等。
按最新要求，成功、正常超时、手动终止均自动保留，不等待审核按键。
旧同步模式后台写完后仍须再次按315开始下一轮；当前周期模式可接受保存期间按下的315，
在保存完成后开始下一轮，不会无按键自动启动。
坏观测、断连、缺回执是数据异常，停止并排除出训练，不伪装为超时。

结束后先发零动作，再后台收尾，随后等待下一次开始。可以按住RB配合摇杆/十字键手动复位，
或单按Back自动回 home；两者都不进入训练数据。Back回位沿用 `gamepad_test.py` 的
`/delta_ctrl_node/home_poses` 服务和 SDK BASE 增量，服务不可用或FK失败时终端会打印原因。
Back回位期间优先于RB摇杆，不能启动新回合；回位结束后松开Back，再按315开始。
场景物体可由人重摆；本程序没有启用机器人拖动/示教模式，
不要直接掰动仍处于伺服控制状态的机械臂。就绪后再按开始。
未再次开始时绝不会自动进入下一回合；退出程序后本入口不再提供手柄控制。

### 各阶段的手柄行为

| 阶段 | 手柄控制与采集 |
| --- | --- |
| 等待开始 | 先松开RB，再按住RB配合摇杆/十字键人工复位，或松开再单按Back自动回home；不采集训练transition。按315进入新回合 |
| 历史预热 | 按315时先发零动作，再建立完整10帧历史，计时已开始；若需RB人工调整，须先松开再按，调整动作不进入训练数据。外部RGB缺失时不会进入`ACTIVE` |
| 运行（终端显示 `ACTIVE`） | RB按住时使用人工动作；松开RB或控制回中时采用零动作。A/B可控制夹爪；有效零动作transition也会保存，不暂停计时 |
| 回合结束、后台保存 | 成功、超时或手动终止后先停止；RB可人工复位，Back可自动回home。周期模式可记录此阶段新按下的315，在保存完成后启动下一轮；旧同步模式不排队 |
| 保存完成、再次等待开始 | 若保存期间没有排队Start，可用RB或Back复位；就绪后松开并重新按315开始下一轮 |

运行中308表示成功、307表示不成功结束；Back在运行和历史预热期间不执行回位。
成功必须在截止时间之前发生；没有有效transition的空回合不会保留为有效训练回合。
手柄断连会中止当前回合并排除训练；重连后需重新开始。

### 摇杆、十字键与输出坐标

运行中的人工动作与回合外复位使用同一套映射。以下为转换前操作坐标：+X前、+Y左、+Z上。

| 按住RB同时操作 | 转换前动作 |
| --- | --- |
| 右摇杆前/后 | +X / -X 平移 |
| 右摇杆左/右 | +Y / -Y 平移 |
| 十字键上/下 | +Z / -Z 平移 |
| 左摇杆右/左 | 绕X正/负旋转 |
| 左摇杆前/后 | 绕Y正/负旋转 |
| 十字键左/右 | 绕Z正/负旋转 |

摇杆死区为0.15，死区外线性变速；十字键固定速度。平移与旋转分别限制合成幅值。
本采集入口默认10Hz，每步平移模长最多 `1/√3 ≈ 0.577 mm`，旋转向量模长最多
`1/√3 ≈ 0.577°`，对应连续满输入的请求速度约5.77mm/s、5.77°/s；不是实测运动速度。
配置JSON中的 `translation_step_m`、`rotation_step_rad` 控制幅值，单位为m、rad；
本入口不提供独立手柄脚本的 `--scale`、`--speed-mm-s` 等选项。

默认 `sdk_convention="sdk-x-forward-z-left"`：平移与旋转向量先按 `(x,y,z) → (x,-z,y)`
换轴，再将旋转向量转为SDK ABC角，最终发送mm/degree增量。
该预设假设SDK +X前、+Z左、+Y下；现场方向需核对，不能把上表直接当作SDK轴名。

本入口的308已绑定成功、307已绑定手动终止；自动回位使用Back（默认314），
夹爪使用A/B。不要照搬[独立手柄教程](gamepad_control.md)的回位组合键或同时启动其控制程序。

必须由现场操作者部署并启动更新后的 `arm_delta_cmd`，支持 `hil_manual_receipts=true`。
启动检查自动读取实际手动话题，验证接收端订阅和手柄键码；旧版本缺少协议时拒绝启动。
本次开发没有构建、替换或重启现场控制进程。参数声明不是SDK执行成功的证明。

新入口全部动作走接收端的手动通道：保留手柄绕过模型触觉保护的既有语义，
并为回合内指令附加ID、等待回执及命令之后的EEF观测。
回执只证明采用/发送窗口结束，不保证真实位移完成。工作空间、关节等其他限制仍生效。
其他独立gamepad/policy动作发布者必须先停止，不能和本入口同时使用。

确认接收端版本及现场条件后，用一个不存在的目录：

```bash
bash scripts/collect_rl_episodes.sh \
  --output local/rl_episodes/session_01 \
  --episode-seconds 15 \
  --execute
```

此命令启用真实人工控制；无自动模型动作。首次先测试空旷工作区的开始、成功、超时、复位和下一轮。
停止是软件零指令，依赖进程/ROS及接收端；进程卡顿靠接收端断流保护，不能替代硬件急停。

## 数据与退出

`session.json`保存契约；`summary.json`保存回合结果。
回合中主线程只复制快照并非阻塞提交到有界队列（32条，数组约73MB上限加正在写入的一条及元数据）。
独立线程执行压缩、写盘和fsync；不是把整段存内存、结束才开始写。
结束后先停止动作，再在后台完成所有写入/末条标签处理与最终清单发布。
等待后台完成期间先松开再按RB可复位，不允许新回合开始；主线程会继续处理手柄。
队列满或磁盘错误会停止当前采集回合并排除训练，不能静默丢帧后仍标记ready。
若磁盘永久卡死，无法保证后台收尾时限；断流保护/现场急停仍必要。
每段 `episodes/<id>/` 包含当前/后继完整观测、采用动作、来源、奖励、结束标记和指令回执审计。
`ready.json`代表完整有效回合，`discarded.json`代表排除但保留供诊断的记录。
Ctrl+C优先请求停止，保留已写文件；未完成回合标记排除，不虚构终止奖励。重复Ctrl+C不打断正常收尾。
写盘错误至少中止当前回合；连排除标记也无法保存时退出。断电、SIGKILL不保证收尾，只有ready的完整回合允许导入。

采集来源记为online human，因此后续可按现有导入规则进入RL与Demo两流，成功和有效截断均自动保留。
这里只输出回合文件，不启动训练、不自动入运行中的经验池。训练需要匹配的contract和recipe，
不能直接用旧检查点路径代替初始化步骤。历史窗口未去重，磁盘占用可能较大，应先做短回合检查。

后续夜间工作应是离线检查数据质量、训练/验证对照并保存候选模型，不会自动部署新策略或无人看守控制真机。
