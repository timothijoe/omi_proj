# 统一健康监控与过期输入门控

状态：2026-10-26整理，来自10月24日讨论；**下述系统级方案未实施**。
现有能力是[RViz V2诊断和训练网页](../modules/visualization.md)，当前采集路径的过期输入门控缺口见[传感器](../modules/sensors.md)。

## 为什么需要

10月24日外部相机断流后缓存旧RGB继续进入训练，最终清理20个已入池回合。
进程活着、消息header变化、camera mask为1和画面仍可见，都不能单独证明观测有效或工作正常。
监控需要区分进程存活、工作进度、数据有效性与下游保存／导入结果；绿灯不能代替训练门控。

## 建议结构

| 部分 | 职责 |
| --- | --- |
| 独立后台 | 采集统一健康证据，判定状态，保存故障开始／恢复记录和候选受影响回合 |
| RViz简要总览 | 操作时显示当前异常、原因、持续时间及状态更新时间 |
| 现有训练网页 | 详细指标、进程／日志入口、事件时间线和回合审阅 |

后台不依赖RViz启动或存活，RViz本身也是监测对象；两种界面消费同一份状态。
可以复用V2状态和Actor/Learner遥测，不重复解码全部图像。ROS diagnostics是候选接口，具体包和状态格式尚待确定。
第一版重点是可复核的异常记录与回合关联；不在只读监控中附带自动重启、删除数据或控制行为变化。

## 检测语义

- 本地进程核对PID与启动身份，远端缺少源端证据时显示未知／不可达，不能断定进程退出。
- 心跳和工作进展分开，复用`emitted_ns`与`progress_ns`；Actor等Start、Learner等数据属于有解释的空闲。
- 源接收年龄、频率、header重复／倒退、载荷合法性分别记录。相同图像可能来自静止场景，不自动判死机。
- 绘图worker要看输入／输出和绘图耗时，RViz GUI响应还需独立证据，不能只看进程存在。
- 反馈、指令接收、回执接受、SDK提交和实际运动分开。参数服务可访问不等于接收端控制循环健康。
- 保存链检查写入错误、ready/imported进展、积压和磁盘空间；监控自身失联时前端标记过期。

事件包含组件、主机、run/session、最后正常／首次异常／首次恢复观察时间、证据和阈值。
本地持续时间使用单调时钟，跨机需记录时钟来源与本机观测时间，保留恢复区间的不确定性。
回合关联考虑十帧窗口跨故障边界的旧帧引用；候选受影响与确认坏样本分开，不按时间重叠自动删数据。
若要精确追溯模型更新，还需另外设计batch样本来源记录，现有日志无法还原每次梯度成员。

## 待办与验收

| 顺序 | 工作 | 交付／验收 |
| --- | --- | --- |
| P0 | 过期输入采集／入池门控 | 定义必需源、年龄阈值、历史窗口恢复条件，模拟旧图不能通过训练有效性判定 |
| P0 | 断流时动作／回合处置规则 | 明确暂停、结束、禁止策略输出及恢复语义；不与只读监控混成一个隐式开关 |
| P1 | 统一组件与状态结构 | 分清未启用、未知、正常空闲、异常；状态都有证据来源和时间 |
| P1 | 独立后台与事件记录 | 低频有界采集／落盘；RViz关闭后继续，监控失败不掩盖旧快照 |
| P1 | 故障与回合关联 | 提供候选回合、观测窗口和可复核原因 |
| P2 | RViz总览与网页详情 | 同源状态、一致阈值；断连显式过期；现有网页V1桥接不能冒充V2支持 |
| P2 | 隔离故障注入 | 源停止、进程暂停／退出、只有心跳无进度、正常等待、落盘失败、监控和RViz重启 |
| P3 | 现场持续验收 | 跨机低频／时钟、长时间GUI稳定性、CPU/GPU／磁盘开销、新采数据质量 |

这份清单延续[10月24日讨论记录](../archive/cross-cutting/records/oct24_development_checkpoint.md)，不将建议阈值当作已确定运行参数。
完成监控不代表完成数据门控；从BC空池重启也不能替代后续数据的新鲜度验收。
