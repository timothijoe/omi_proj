# 双相机 ROI 选择约定：第一版

记录日期：2026-10-03。用户要求先用文字保存当前外部相机与腕部相机的裁剪方式，
作为第一版基线，后续再调整；腕部采集异常暂缓处理。
本约定记录现有行为，不表示已经完成相机标定、最佳ROI搜索或策略效果验证。

后续已实现在线 `--image-mode full|roi` 开关与128×128 ROI话题；整图能力保留，策略/录包接入待做。
传输负载、显示端放大及训练/推理插值一致性要求见[采集纪传体](../agent/hardware/evolution/sensor-collection.md)。

## 1. 共同约定

ROI是原始彩色图像中的正方形裁剪区域。此处的clip/rect表示裁剪，不是相机去畸变，
也不是整张原图直接拉伸到正方形。按“先裁剪，再缩到128×128，再按需要放大显示”处理。
图像使用左上角为原点，X向右、Y向下，尺寸写作宽×高；解码后使用RGB。

使用归一化中心和短边比例，避免直接绑定某个分辨率。对于宽W、高H的图像：
边长取 `max(1, round(min(W,H) * 边长比例))`；中心像素分别取
`round(W * 中心X比例)` 与 `round(H * 中心Y比例)`。
左上角为中心减去`边长 // 2`，再限制在图像内；以代码中的Python round及整数除法为准。
先确定整数裁剪范围，再做缩放，不从已经缩小的整图上二次裁剪。

实现参数来源：`src/omi_hil_rl/real/observation.py` 的 `ObservationConfig`，
几何计算复用 `_crop_square_resize_nearest`。当前新录包看板使用固定框，
不进行自动目标跟踪，也不会因机械臂运动自行移动ROI。

## 2. 外部相机 ROI

输入话题为 `/camera/camera/color/image_raw`，即当前外部视角彩色图。
裁剪中心取图像宽度的 **50.7%**、高度的 **42.6%**；边长取图像短边的 **40%**。
这个框大致在画面水平中央、垂直中央稍上，用来保留当前夹爪与插孔作业区域。
这是沿用已有观测配置的固定选择，不保证对换位、换相机或新任务自动适用。

在bag_004的640×480图像中，中心像素为(324,204)，边长192像素；
左上角为 **(228,108)**，裁剪范围为 **192×192**，数组切片为
`image[108:300, 228:420]`，最终输出128×128。

当前新录包看板的外部128预览使用**最近邻缩放**，与现有BC外部图像预处理一致。
旧record010的人类看板使用同一ROI几何、但用Lanczos生成预览，不能声称两者逐像素一致。

## 3. 腕部相机 ROI

bag_004输入话题为 `/tj/dm_camera/camera/color`，源编码为bgr8，解码后转成RGB。
旧record010入口使用 `/tj/dm_sensor/camera/color`；本版借用其裁剪规则，不把旧话题名称
强行套到新包。腕部裁剪中心取宽度的 **50%**、高度的 **70.4%**；边长为短边的 **36%**。
与整图中心框相比，该框明显靠下且更小，更集中于当前夹爪／插孔区域。

在bag_004的1920×1080图像中，中心像素为(960,760)，边长389像素；
左上角为 **(766,566)**，裁剪范围为 **389×389**，数组切片为
`image[566:955, 766:1155]`，最终输出128×128。

当前腕部人类看板用**Lanczos**将裁剪缩至128×128，与旧看板`prepare_camera`的128图
逐像素一致；再用双线性插值放大为278×278显示，不增加原始信息量。
黄色框画在原图上帮助核对范围，框线不会进入128裁剪图。
原先临时的1080×1080中心大方框已被替代，不属于本第一版约定。

## 4. 可视化与训练边界

右上角显示腕部原图和放大的128裁剪图；左上角显示外部原图和128预览；
右下角保留双侧原始触觉。裁剪与绘图在离线缓存阶段完成，RViz播放读取结果。
当前缓存版本为 `wrist-review-v2-legacy-roi-lanczos-128`。
“ROI约定第一版”是本说明的基线名称，不等于已废弃的中心裁剪缓存v1。

旧七关节BC与EEF v1仍只接外部相机。新增[EEF v2](../agent/training/evolution/eef-action-space.md#v2可选腕部相机与输入源标记)
可选择腕部输入，沿用本页ROI几何，训练/推理统一使用最近邻缩至128×128，再按uint8/255归一化。
腕部人类看板仍采用Lanczos；不能直接把预览图等同于策略输入。
新旧契约分别保存，旧权重不被静默改成双相机。

新包CameraInfo的distortion_model为空，此阶段不执行去畸变。ROI也不能解决相机采集
近乎冻结、坐标系标定、时钟同步或图像缺失问题。调整ROI后需更新缓存版本和训练数据契约，
确认裁剪框覆盖接触区域、保留必要上下文，避免混用不同预处理版本的数据。

操作入口见[腕部回放教程](../../tutorials/wrist_bag_review.md)，
