# 录包行为克隆与ROS影子推理：第一版目标

2026-10-03用户授权：先记录目标，再实现基于当前外部record001录包的训练集、
真正的模仿学习训练，以及用ROS回放模拟在线传感器输入的policy inference。

## 两个交付目标

1. 从ZIP/完整MCAP录包构建可追溯训练集，训练行为克隆（BC）初始策略，保存权重、
   预处理契约、归一化统计和指标，并提供可复现命令。
2. 在独立localhost ROS域回放观测消息，独立推理节点订阅并组装输入，
   运行上述权重，只发布影子预测与诊断，不连接硬件、不发送实际控制命令。

## 第一版输入与标签

- 已有外部彩色相机128×128 ROI；腕部相机缺失，不作为必需输入。
- 双侧deformation(2)+shear(2)+depth(1)，分别降采样为16×24×5；六维wrench各一组。
- 左臂7轴实际位置。暂不输入夹爪开合、存在坐标映射疑问的eef位姿。
- 标签先使用录制左臂关节目标；检查消息定义、单位/顺序和生产者语义。
  未获现场证实的含义必须明确作为实验假设，不能把预测用于真机。
- 训练/推理复用预处理、字段顺序、时序选择与有效性规则；控制指令绝不作为观测输入。

## 验收要求

- 源header为参考，因果选择不晚于决策点的观测；保留年龄/时间，拒绝缺失或过旧数据。
  必须检查时钟，显示年龄不证明采样时刻同步。
- 完整episode划分训练/验证；统计只用训练集。单包不能随机帧划分并冒称泛化验证。
- 单个约13.55秒包先做明确标记的过拟合/管线测试，不声称得到能插孔的策略。
- 实际运行训练，证明权重更新及预测可加载，比较简单基线；保存准确指标。
- 实际运行ROS消息订阅推理，检查预测、耗时、过期/暂停、循环历史清理与无控制topic。
- 录包影子推理不是闭环：预测不会改变后续传感器数据。
- 原看板及未提交文档工作保持不动，数据/缓存/权重留在Git忽略的local或data目录。

## 人工接管与类型化动作接口（待实现）

2026-10-03 用户认可参照原版 HIL-SERL 的“先选择动作，再统一执行”方向。
原版源码依据见[接管与经验记录](../agent/training/evolution/hil-serl-reference.md#人工接管动作记录与训练采样)，
术语见[领域术语](../../CONTEXT.md)。以下是后续设计约定，不是已有 ROS 接口。

- 策略候选和人工候选使用相同的类型化动作结构，但分开来源入口；策略输出始终只代表
  模型建议，不混入人工动作。不能靠两个发布者向同一指令 topic 发布、以先后顺序抢控制权。
- 统一选择模块依据接管状态选出一个动作；干预和不干预共用选定动作出口，携带来源标记。
  `POLICY / HUMAN / HOLD` 是拟议状态，具体枚举与消息字段尚未冻结。
- 策略可以在接管期间继续推理，用于对比与记录；没有被采用的预测不能作为这一步实际
  交互的动作标签。人工输入消失、过期或断连不能直接等同于允许恢复自主控制；恢复条件
  与安全保持行为必须另行实现和验收，不直接照搬原版输入回零即恢复的行为。
- 日志区分策略候选、人工候选、选定动作、最终下发目标与实测反馈，记录来源、观测参考
  时间、决策时间、有效性以及拒绝/限幅信息。动作单位、关节顺序或坐标系必须明确。
  训练动作应与定义的策略动作空间及执行链路对应，安全修改的处理规则仍需单独确定。
- 可用 `ActionProposal`、`InterventionState`、`ActionDecision` 表达这些职责；它们只是
  建议名称，尚未创建 `.msg`。策略和人工候选分 topic、决策统一出口是 ROS 工程方案，
  不是原版 HIL-SERL 的 topic 命名或传输实现。

当前 `training.bc_shadow` 的 `/omi/shadow/prediction` 仍为 `std_msgs/msg/String` JSON，
只发布影子预测。旧关节链路尚未替换String；新独立[EEF实验](../agent/training/evolution/eef-action-space.md)
已实现类型化策略候选。人工输入、选择模块和真实控制输出仍未实现。
后续替换 String 时仍须保留 shadow 隔离，发布类型化预测不等于授权控制机器人。
当前 BC 的七关节绝对弧度目标仍是待现场确认的假设，不能直接换成原版末端增量动作。

记录见[本次编年](../agent/training/chronicles/2026-10-03-intervention-action-contract.md)。
