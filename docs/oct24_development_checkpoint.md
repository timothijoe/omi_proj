### 4.2 监测对象和判断层次

| 对象 | 需要检查的证据 |
| --- | --- |
| 外部相机、腕部相机、触觉源 | 本机接收频率／间隔、最后消息年龄、header变化、载荷合法性；可取得时补源端心跳 |
| 绘图worker、RViz | 进程状态、工作心跳、输入／输出进展、绘制耗时；GUI是否响应需要另外的证据 |
| 机器人EEF／关节反馈、接收端 | 反馈年龄、接收端心跳／状态、命令回执；参数服务可访问不等于控制循环正常 |
| Actor | 心跳、主循环进展、当前阶段、实际模型输入年龄、推理／发送／保存进展 |
| Learner | 心跳、训练／等待阶段、导入与更新进展、发布确认 |
| 保存与导入链 | 回合保存完成、ready/imported、积压及最老等待时间、文件写入错误、磁盘容量 |
| 监控后台自身 | 最后采集／发布时间、内部错误，前端独立识别状态过期 |

不能用“PID存在”“ROS节点可见”或单一绿灯代替上述多层判断。
远端进程没有可验证的源端信息时应显示未知／不可达，不能仅因本机没有消息就断定远端进程已退出。
相同图像可能是静止场景，内容重复只能作为可疑线索；header变化也不能单独证明曝光新鲜。
正常等待Start、等待人工示范或等待新数据，应结合阶段解释，不能机械地把训练步数不变判成故障。

### 4.3 事件与数据关联要求

故障事件建议包含组件、会话／启动身份、原因、最后正常／首次异常／首次恢复观测时间、
检测依据及阈值，保留恢复区间的不确定性。频繁异常应合并并限速写入。
本机持续时间用单调时钟；跨机器时钟不可直接相减，事件关联需保存时钟来源和本机观测时间。

关联回合时同时考虑观测历史窗口：故障结束后的窗口仍可能引用故障期间旧帧。
候选受影响回合与确认有坏样本应区分；不凭时间重叠自动删除数据。
后续若需要追溯模型影响，需要额外记录训练batch的样本来源；现有日志不能还原每次更新的成员。
