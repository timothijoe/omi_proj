# 2026-10-02：record010 零载荷触觉基准提取

## 目标

验证 `record010` 是否包含可以恢复双指触觉 base frame 的无接触片段，并把人工判断转成可
重复执行的离线工具。本阶段只读取 rosbag，不连接传感器、不播放 topic、不发布运动命令。

## 实际实现

逐帧检查发现夹爪并非在 bag 最末尾保持松开：约 24.5 秒开始张开，25–26 秒稳定保持
完全张开，约 27 秒再次闭合。外部相机的 25.00、25.24、25.51、25.75 和 26.02 秒画面
均可见两侧橙色指尖分离。最终选择 `25.0–26.0 s`，分别对 A/B 的 mono8 raw 做逐像素
时间中位数，避免把单帧噪声直接作为基准。

新增 `omi_hil_rl.real.tactile_baseline`。它懒加载 ROS 依赖，读取 bag 后保存 A/B NPY/PNG、
含时间戳的压缩 NPZ、相机接触表和 schema version 1 的 JSON 报告。生成器拒绝覆盖已有
输出目录；本次生成物位于 `local/tactile/record010_zero_load_25_26/`，由 `.gitignore`
排除。

## 验证证据

- A raw 参与中位数的帧数为 24，B raw 为 23；两者均为 `270×360 uint8`。
- 窗口内夹爪位置最小值和均值均为 1.0。
- A/B 三维力模长均值约为 0.625/0.472；depth 均值约为 0.00695/0.00637。
- 夹爪张开、A/B 力接近零、A/B depth 接近零五项录包启发式检查全部通过。
- 新增基准聚合、稳定性和零载荷判定测试；完整测试结果为 `44 passed, 1 skipped`。
- 人工查看相机接触表后确认 25–26 秒确实张开。

## 限制与影响

bag 没有记录厂商序列号；现有日志只能证明工作区出现过 `X26040345` 和 `X26040546`，
不能可靠证明其 A/B 对应关系。因此基准报告中的 serial 映射保持空值，尚未调用 Daimon
SDK 重建 deformation/shear。厂商文档也没有声明 wrench 单位，本次阈值仅用于同一录包的
无接触候选验证，不能解释为 N 或 N·m 的校准阈值。

这次工作排除了“没有可用 base frame”这一阻塞项。下一步应由设备枚举、录制端元数据或
现场标签确认 A/B serial，并在隔离环境中验证同帧 SDK 输出后，才接入数值向量 topic 和
OMI 自绘箭头 dashboard。
