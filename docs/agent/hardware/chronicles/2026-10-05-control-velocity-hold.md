# 2026-10-05 手柄、策略速度保持与夹爪启用修复

用户报告键盘控制更平顺，要求把话题的20次批量IK改成每次IK后立即下发。
首版已完成，但运行日志仍出现旧批次未走完被替换；该改动未消除等待下一条消息的空档。
用户反馈增大手柄scale后改善，随后明确授权手柄与神经网络均采用速度保持。

当前实现：10Hz名义增量乘以各自command_rate得到速度，200Hz每周期生成小步并IK、
限幅、包络检查和下发。新消息更新速度，零消息立即停止，两个通道默认0.25秒断流停发。
断流和控制定时器使用单调时钟。调度延迟不补发大步；策略保留触觉保护与后退限速。
没有增加独立速度上限或加速度平滑，也没有修改网络权重、输入归一化或动作scale。

HIL按一个名义周期结束观察回执，`velocity_window_sent`仍可继续保持速度，
显式标记`velocity_hold_continues`，不把SDK发送当作物理位移完成。
旧20步队列描述已在当前架构和操作教程中修正；早期编年保持历史含义。

A/B夹爪故障另有明确证据：运行中的手柄命令没有任何gripper参数，原入口静默禁用。
直接入口现默认启用项目已有地址、SDK与标定文件，提供`--no-gripper`选项和启动状态输出。
SDK依赖导入通过；实机开合效果未在本次修改中验证。

验证：接收端/保护/HIL回执70项通过，HIL运行时16通过、1跳过。
包括真实ROS定时器配合模拟机械臂持续超过20步、停止和接管回归。
