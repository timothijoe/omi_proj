## 结构

V1在同一个默认单线程executor中执行图像订阅、整图绘制、发布和每帧PNG保存，显示端负载会影响其自身接收统计。
V2取消整张传感器合成图，外部原图与腕部ROI直接进入RViz独立Image显示项。
首版还有腕部完整图和双指raw，随后按用户要求移除。
外部ROI和双指deformation/shear/depth各有独立进程；每个worker的接收/心跳线程与转换循环分开，
只保留最新待处理消息，不持有状态锁做绘图。无新数据不重复绘制，过时结果不作为正常图发布。
单个worker坏数据、卡住或退出不会停止其他原图和派生图。所有绘图仍共享主机CPU，RViz仍共享GUI/GPU。

独立probe使用serialized订阅，仅检查CDR1 Header前缀并统计回调到达，不解码大图或绘图，不写磁盘。
它另订阅派生输出及worker心跳，报告输入到达频率/间隔、面板输出频率、绘图耗时与worker接收至publish返回耗时。
诊断进程只绘制小型文字表，并低频保存JSON；不重新合成传感器画面，不每帧压缩保存PNG。
状态不使用源header作为显示阻断条件；源时间、重复/倒退计数保留用于诊断。

实现：`real/grid_live_v2.py`负责角色、ROS和生命周期；`grid_live_v2_core.py`负责面板、统计及转换；
`grid_live_v2_control.py`负责只读参数查询、EEF／命令／回执订阅与独立控制状态图。
`scripts/grid_live_observation_v2.rviz`是独立布局，开发时可用`build_grid_live_v2_layout.py`重生成。
布局显式设置`Hide Right Dock: false`，避免遗漏键时RViz沿用左侧隐藏值；运行时兼容补齐旧模板。
面板整体隐藏的F11／侧边箭头恢复方法见教程；该布局缺陷已修复，用户描述的延时消失尚未复现。
输出在 `/omi/live_grid_v2/`；显示模型运行于独立子进程，复用原模型逻辑但使用V2命名空间，未改V1源码或现场TF。

## 解释边界

探针的RECEIVING表示消息到达，不代表载荷正确、曝光新鲜或设备内部采样正常。派生图另做数值校验。
原图断流时RViz可能保留末帧，须结合独立RX age；派生图500ms后显示STALE，外部ROI保留像素并加红框／秒数。
去掉raw/full面板仅改变查看器，不停止上游发布，也不改变录包和训练。
Draw包含解码/校验/转换；RX->pub不包含曝光、前置网络传输、DDS送达RViz及屏幕呈现。
任何状态、频率或图表都不证明物理同步。未变更策略预处理、训练输入、动作发布或控制端。

EEF源四元数转换为ZYX欧拉角仅供显示；命令为接收端SDK坐标下mm／ABC度名义增量，
不与EEF绝对位姿混称。两通道独立保留最近收到的消息，超过250ms变灰并标STALE，不补零。
条形图范围是显示参数，超出仅截短绘图并保留实际数字，不限幅机器人。
控制栏仍是一个独立显示进程，失联由接收探针标为WORKER_SILENT，不阻塞九幅观测图。
