## 实现与契约

- `scripts/spacepilot_test.py`：终端预览/显式发送入口；无需 GUI，默认无 ROS 发布。
- `real/spacepilot_control.py`：纯六轴映射、独立倍率、模式及启用状态；内部使用米/弧度名义增量。
- 复用 `hardware/spacepilot_pose.py` 的 SpaceNav、方向映射、死区与单轴滞回。输入连接新增可选 reset 通知，用于清除机器人入口的启用状态；演示窗口不注册该回调。
- 复用 `real/sdk_action.py`，只在发布前换轴一次并将旋转向量转 SDK ABC；输出 `Float64MultiArray[6]`，单位 mm/ABC degree。
- `real/receiver_preflight.py` 增加可选 `expected_manual_rate` 检查，校验 `manual_command_rate` 与 `delta_frame=base`。旧调用默认行为保持。新入口检查连接/授权配置及订阅后，自动选择 `manual_delta_topic`。

早期网络现场：domain13/LOCALHOST探测无接收端，SUBNET下参数服务正常。后续用户在本机启动接收端后，两种发现范围均可见；当前应按实际部署匹配。接收端两路订阅在图中均返回 `_NODE_NAME_UNKNOWN_` / `_NODE_NAMESPACE_UNKNOWN_`。新入口显式开启 `allow_anonymous_subscriptions`：参数校验通过后，允许各配置话题恰有一个匿名且为 Float64MultiArray 的订阅，并在启动日志提示；拒绝已知错误节点、错误类型或歧义端点。匿名匹配无法证明节点归属，严格节点名校验仍为其他入口默认行为。此次真实网络只读完整预检通过，未发布动作。

默认速度 10 mm/s、10°/s，默认 10 Hz。有效速度为基础速度 × 公共 scale × 各组 scale，各组三轴按范数限幅；0 倍率禁用对应组。输入循环每次休眠至多10 ms；从零输出变为非零有效动作时，本轮立即发送首条，并从实际发送时刻重新计下一个周期。持续非零运动即使方向/力度变化仍按配置频率发送，默认10 Hz；松键/回中/失效的零动作同样立即发送，恢复有效运动时再立即起动。不补发积压动作，不改变每条名义增量、速度或坐标转换。立即指发现有效输入后的同轮发送，不代表设备到物理运动零延迟。

默认实体 3（按当前用户反馈改为 ID19）按住启用，支持显式 toggle；初版采用 GUI 历史 ID14，未匹配本次实体按键。`--enable-button` 可覆盖，实际事件 ID 为准。模式为命令行 `all|translation|rotation`，不复用 GUI 的实体 1/2/3 模式切换。独立入口无夹爪、回位、RL 仲裁或数据录制。读取的是旋钮输入而非演示位姿；没有 Tool 局部坐标模式。

## 停止与验证边界

共用控制链可用 `scripts/record_control_response.sh` 做独立只读记录：首个非零手动指令触发45秒采样，保留前2秒，记录指令、关节位置/速度、EEF、回执和接收端警告及参数。时间是本机接收时间，不能等同SDK提交或物理输入时刻；工具不发布动作、不改变接收端，输出位于 `local/diagnostics/control_response/`。已验证参数读取、反馈采样、JSON输出及退出；19:32用户四段运动记录也已分析，阈值与限制见开发快照。

首条立即发送后用户仍反馈比手柄迟滞。只读空闲测量：驱动poll最大0.258 ms，手动topic零指令接收间隔约103–105 ms；测量期间无鼠标输入，不能代表运动端到端时延。运行进程已加载首条立即发送修改，进一步区分起动、转向或停止迟滞，暂未改变频率/速度。证据见编年记录。

用户进一步强调起动与停止迟滞，描述按“松开旋钮、实体3仍按住”理解，重点检查回中残余。新增 `scripts/spacepilot_input_check.py`，由用户回车启动只读采样，记录原始六轴、启用键和候选变化；本机接收时间不代表物理松手时间。普通手动零指令在本地接收端只停止新增SDK目标，不执行反馈位置保持，不能保证物理立即停止。已获得指令/反馈采样，但仍缺物理回中和SDK目标的联合测量，未确认现场根因；未调整死区或接收端控制方式。

2026-10-17待定位：用户报告三个平移方向似乎均变成机器人上下运动。本机只读查询驱动配置为六轴一一映射、灵敏度均1、无反转/交换。新增 `--debug-input` 后，用户提供前推/左推/上提的纯平移单轴预览，分别输出 SDK +dx/+dz/-dy，未发生平移轴合并；采样原始输入同时有明显旋转分量，旧 all 模式会输出这些旋转。后续已有四段前后指令与反馈对照，但尚无三方向完整标定，不能把旋转混入认定为唯一根因。方向映射本身未改，不能宣称真机问题已修复。

输入超过150 ms未更新发零；断连、设备变更与循环停顿超过250 ms清除启用，停顿后重建输入连接。退出尽力发零，接收端仍负责断流处理。检测到其他手动/策略发布者即退出，图发现仍存在延迟，不能保证分布式互斥。

离线测试覆盖六轴方向、独立 scale、合速度、模式、死区、hold/toggle、过期/断连、接收端参数匹配、模拟 ROS 发送及退出停止。真实只读预览验证驱动连接和 CLI，不构成物理按键逐项或机械臂运动验收。原 GUI 仍为独立演示；新增发送代码不表示已经验证真机 TCP、安装方向、停止距离或操控手感。
