# 统一训练监控：状态、链路与只读审阅

更新：2026-10-09。入口 `scripts/view_training_monitor.sh`，
操作见[统一监控教程](../../../../tutorials/training_monitor.md)。

## 实现与边界

`hil.training_monitor` 使用标准库 HTTP 服务，仅监听 `127.0.0.1`。它读取指定会话的
监控快照、旧状态、原始审计、ready/imported 标记和 replay manifest，不加载训练网络，
不重开经验池，不获取写者锁。逐帧 API 延迟调用既有 `PeriodicReview`，只接受已索引的回合 ID。
静态 HTML/JS/CSS 随 Python 包分发；无新增第三方运行依赖或外部服务。

`hil.telemetry.TelemetryWriter` 由 Actor/Learner 在持有各自 owner lock 后创建。
生产循环只更新内存标量与不可变观测引用，后台线程约 2 Hz 更新原子快照。
图像至多约 1 Hz 重绘并缓存，快照仍独立更新；触觉箭头隔点采样为 12×8，并注明固定尺度。
每个角色独立文件及事件日志；事件队列上限 128，观测仅保留最新引用。
写者 I/O 故障打印诊断并重试，不改变训练或控制判定；监控事件不是可靠数据交接账本。
高频心跳不做 fsync，原训练数据的持久化规则保持原值。

Actor 的 ROS pump 提供接收年龄、Header 年龄、计数差分频率、输入拒绝、窗口 mask、
当前匹配候选推理耗时和手柄状态。周期主循环报告仲裁 gate、命令、回执及审计队列；
保存阶段显式标记 SAVING。保护话题只读订阅，不触发任何服务或开关；缺少话题时状态未知。
Learner 报告导入、等待、训练、发布确认、当前进程计数和耗时，不改变更新预算。

## 新鲜度与证据语义

快照 `schema=omi-monitor-v1`，包含独立 session、PID、`emitted_ns` 与 `progress_ns`。
前者由写者推进，后者仅由生产循环推进；主循环卡住时，后台仍写心跳不能伪装成正常工作。
旧 `status.json` 和 `async_state.json` 永远只作历史快照。异常 JSON 单独报告，页面保留可读取部分。

数据链累计 ready/imported 条数与 replay 当前占用分开显示。权重区分别显示训练、
已确认发布、实际加载；无发布遥测时保留未知，不推测 `.pt` 内容。
版本计数仍对应 Critic 更新，Actor 实际参数变化另由更新次数及现有漂移指标解释。
页面状态正常不能证明策略性能、安全阈值、设备新鲜度或 EEF 物理因果已通过验收。

## 当前验证

真实已有会话只读统计与之前审计一致：10 个完整回合、1 个中断暂存、1959 tick、
1059 有效且已导入 transition、0 待导入、1 条成功奖励；Actor 保存版本 650、
Learner 更新计数 6502。旧会话没有新增遥测文件，没有修改原始数据或训练权重。
软件测试覆盖新鲜度、历史降级、监控写盘故障、生产者不等待写盘、图像一致性、
只读 HTTP、非法回合/槽位、保护状态，以及真实 SAC 对合成数据的导入/更新/发布/退出。
相关异步、周期、BC、采集与 runtime 回归作为本轮检查；数量见[开发编年](../chronicles/2026-10-09-training-monitor.md)。

当前环境无可连接的浏览器，尚未完成实际网页视觉验收；未启动设备或真机训练，
后台图像渲染与训练并发的端到端开销仍需现场测量。自动策略刷新频率、UTD 预算控制、
gRPC/队列替换磁盘交接及远程部署均不在本轮实现范围。
