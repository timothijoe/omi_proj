### 特别说明：单位换算与坐标系变换

**毫米/米、度/弧度是单位换算，不是坐标系变换。**
“双方都称基坐标系”也不自动证明原点、轴方向和末端参考点一致。
当前策略的 `base_link` 与控制端基坐标系是否一致，仍需核实；下面分别说明两种情况。

#### 1. 同一基坐标系、同一末端参考点

沿用当前策略的平移差和上述暂定旋转向量约定：

```text
policy = [dx_m, dy_m, dz_m, rx_rad, ry_rad, rz_rad]
controller = [1000*dx_m, 1000*dy_m, 1000*dz_m,
              (180/pi)*rx_rad, (180/pi)*ry_rad, (180/pi)*rz_rad]

p_target = p_current + dp_base
R_target = Exp([dr_base]×) R_current
```

`[dr]×` 表示由旋转向量构成的反对称矩阵，Exp为旋转矩阵指数。
旋转向量的方向是旋转轴，模长是旋转角；三个分量不是依次执行的欧拉角。
平移按基坐标轴表示，不随腕部朝向改变；旋转使用基坐标轴并左乘。
这里平移沿用策略现有定义，控制端是否同样解释仍待验证。

例：策略输出 `[0.001,0,0,0,0,0.0034906585]`（m/rad），
对应控制接口约 `[1,0,0,0,0,0.2]`（mm/度）。
这是一次100 ms周期的增量，不是速度；转换时不再乘或除0.1秒。

#### 2. 两个基坐标系轴向不同

设 B 为策略基坐标系，C 为控制端基坐标系；`R_CB` 把B中的向量表示转换为C中的表示。
当两端描述同一个末端参考点、坐标系之间的关系固定且采用右手坐标系时：

```text
dp_C = R_CB @ dp_B
dr_C = R_CB @ dr_B
controller_translation_mm = 1000 * dp_C
controller_rotation_deg = (180/pi) * dr_C
```

这是同一物理增量换坐标轴表达，再换单位。`R_CB` 必须来自已知坐标定义或标定，
不能凭相机画面里的“前/右/上”猜测；相机坐标也不能直接当作机器人基坐标。
上述公式里的dp是同一点的有限位置差，不是一般空间速度twist。

若转换的是绝对位姿，则还需平移外参：
`p_C = R_CB @ p_B + t_CB`、`R_C_E = R_CB @ R_B_E`。
固定的 `t_CB` 在同一点的位置差中抵消，所以不加到上述增量里。
若一端是法兰中心、一端是TCP，两端参考点不同，不能仅使用上述旋转换轴公式；
必须结合TCP偏置和当前/目标姿态转换完整位姿，再求相同参考点的增量。

**当前状态：这些是明确记录的适配约定和公式；尚未实现或启用真实控制桥接。**
用户指定的基坐标系旋转向量假设不等于两端基坐标系外参已验证。

接收端需核实：

1. 核实两端基坐标系的轴方向、正负号和末端参考点；平移是否符合现有策略定义。
2. 验证当前“基坐标系旋转向量、左乘”的暂定约定是否与接收端实现一致。
3. 增量相对实时反馈位姿还是上一次目标累加；这影响与训练代理标签的对应关系。
4. 每条命令是否在100 ms内插值20步；新命令到达时替换、抢占还是排队。
5. 输入中断、积压和超时行为；候选失效后不得继续使用旧动作。

单轴方向测试成功支持该测试接口可用，但不足以区分多轴旋转组合的数学定义。
因此当前确认的是发送格式和节奏；尚未完成或启用真实控制桥接。
