## 回合、奖励和入池

默认采用可配置手柄按钮：Menu 开始、Y 成功、RB 按住人工接管、结束后 A 保留/B 丢弃。
运行中按 B 中止并丢弃本段；按钮映射仍可根据现场偏好调整。

开始按钮触发后立即计时，默认 15 秒，包含十帧历史预热。
reset 清理历史并等待开始按钮；任务和机械臂的物理复位由人完成。
成功 reward=1、terminated=true；通常运行 reward=0；超时 reward=0、truncated=true。
超时允许 Critic bootstrap，成功终止禁止 bootstrap。
若截止发生在两次命令之间，将最后一条有效 transition 标为截断，不新增虚构动作。

每段先写入磁盘暂存文件，人工审核保留后才交给 learner。
审核按 episode，训练按抽样的 transition minibatch；learner 可以在 actor 收集下一段时持续更新。
建议根据数据是否有效来审核，正常失败和超时回合也有学习价值，不宜只保留成功回合。
断线、坏观测、过期动作、拒绝/修改命令、缺少后继反馈等异常段会丢弃。

| 来源 | Demo 流 | RL 流 |
|---|---|---|
| `--offline-demo` 成功且全人工的回合 | 是 | 否 |
| 在线 policy transition | 否 | 是 |
| 在线 human transition，包括有效失败回合 | 是 | 是 |

两流都有数据时，默认每批各半。当前 BC 的未来 EEF 差分代理标签不能直接作为执行命令导入。

## 数据和执行边界

Replay 使用指定目录下的 memmap ring，训练只读取所需 batch。
模型、batch 与 OS 页缓存仍占内存；图像历史暂未去重，暂存回合也占用磁盘。
当前单环覆盖会覆盖旧 Demo，尚不是原版独立容量的两个物理池。

Actor/Learner 使用本机目录交接与原子权重文件，尚不支持跨机器 AgentLace/gRPC。
Actor 在回合边界加载策略。恢复支持干净 checkpoint；任意断电或强制终止后的事务恢复尚未实现。

ROS 默认只读，显式 `--execute` 才创建最终动作 publisher。
回执报告指令采用、SDK 子指令发送、队列取消或故障，不能证明实际 TCP 完成请求位移。
Replay 的动作语义是 accepted_command，不是按反馈估计的实际位移。
现场 TCP、安装轴转换、UserFrame 和反馈链仍需验收。

## 已有验证证据

以下数字来自实现阶段，本次文档整理未重新运行训练或测试。

- 软件测试：42 通过；CPU 环境中的一个 CUDA case 跳过。
- 独立 CUDA 专项：3 通过，包括真实多模态网络更新与恢复。
- ROS 接收端与保护回归：48 通过；一项既有 Jointfeedback 字段测试因安装消息 schema 不匹配排除。
- 真实 encoder 使用合成输入，以 batch32 完成两次 CUDA 更新；峰值已分配显存约 813 MiB。

软件闭环与 GPU 更新证明实现能运行，不代表策略已经学会插入。
完整形成过程见 [实现编年](../chronicles/2026-10-05-hil-actor-learner.md)。
