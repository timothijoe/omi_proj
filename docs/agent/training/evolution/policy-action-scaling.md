## 当前已经实现：平移、旋转分别保方向限幅

模型反归一化输出六维增量 `[dx, dy, dz, rx, ry, rz]`。前三维是基坐标系平移向量，单位m；后三维是基坐标系旋转向量，单位rad，不是欧拉角，也不是绝对姿态。

处理顺序：

```text
模型输出反归一化
  → 整体乘 policy_scale
  → 平移、旋转分别按范数等比例限幅
  → 有效性和时效门控
  → RB人工/policy仲裁
  → sdk-x-forward-z-left换轴及旋转向量转ABC
  → /omi/action/decision
```

设乘完policy_scale的平移向量为p，旋转向量为r，单步上限分别为P、R。当前策略为：

```text
sp = min(1, P / ||p||)
sr = min(1, R / ||r||)
p_out = sp × p
r_out = sr × r
```

某个向量为零时，对应缩放系数取1，不除以零。没有超限的部分保持原值，不放大；不是逐轴裁剪。

默认10 Hz、平移10 mm/s、旋转10°/s，对应每步P=1 mm、R=1°。旋转限幅针对旋转向量的长度，即旋转角度；不对转换后的ABC三个欧拉角逐项裁剪。

这一策略保留平移方向和旋转轴，但sp与sr可能不同，因此可能改变“移动多少，同时转多少”的比例。平移和旋转虽然是不同输出分量，在抓取、插入等任务中可能需要协同，不能认为它们在任务上互不相关。

## 讨论建议：平移、旋转共用一个缩放系数

为了更忠实地保留预训练policy每一步的动作配合，建议采用统一缩放：

```text
s = min(1, P / ||p||, R / ||r||)
p_out = s × p
r_out = s × r
```

零向量对应项不参与限制。两个比值都是无量纲量；不直接将mm和度拼成一个范数比较。

共同系数既满足平移、旋转各自的上限，也保留这一小步中两者的相对比例。代价是限制较宽松的部分不会用满自己的速度上限，这是保留动作配合的结果。

以用户此前输出在policy_scale=0.5之后的幅度为例：

| 处理方式 | 平移合成距离 | 旋转角度 |
| --- | ---: | ---: |
| 限幅前 | 17.08315 mm | 5.13810° |
| 当前分别限幅 | 1 mm | 1° |
| 建议统一限幅 | 1 mm | 约0.30077° |

统一系数约为0.0585372，由平移上限决定。当前分别限幅的旋转系数约为0.194625，两者不同。

统一缩放保留的是当前一步的平移/旋转比例。闭环下一步会根据新观测重新预测，不能保证整条轨迹等同于原轨迹的慢放，也不能靠限幅修复错误的输入坐标或预测方向。
