# 左臂末端增量动作与录包代理标签

硬件接口的新参考见[axis_test 对齐方案](axis-controller-interface.md)：该脚本使用mm/度，而本文训练契约仍为m/rad。**实机后三维暂按基坐标系旋转向量解释，这是用户指定的假设，尚未经接收端核实。** 单位换算与跨坐标系/TCP变换详见该对齐方案。

入口：`scripts/eef_bc.sh {export|train|shadow}`。操作见[教程](../../../../tutorials/eef_action_space.md)，
验证过程见[编年](../chronicles/2026-10-03-eef-action-space.md)。
本轮以左臂6D基座系增量作为可修改的试验默认，不代表用户已冻结最终硬件动作契约。
旧 `bag-bc-v1` 七关节目标和检查点保持原含义。EEF支持原单相机v1及双相机v2，
按保存的契约选择网络；数据/检查点版本和输入源模式必须精确匹配。

## 动作定义

新增离线版本 `bag-eef-bc-v3-grid-receive`，用于oct3正式小矩阵录包：
双视觉shape与v2一致；触觉已池化、腕部已裁剪，不重复处理；无wrench，state为14维。
跨设备header时钟不一致，统一按接收时间选择观测和未来EEF代理标签，原header另存；
这与下文v1/v2的源header对齐规则不同，不能混用版本或运行现有在线shadow。
源消息入口时差超过250ms（EEF50ms）或header超前100ms以上时拒绝；不自动估计时钟偏移。
详细约束与本轮训练确认状态见[正式录包教程](../../../../tutorials/oct3_formal_dataset.md)。

契约 `bag-eef-bc-v1` / `left-eef-base-delta-v1`：

| 项目 | 第一版 |
| --- | --- |
| 控制对象 | 左臂末端；不含夹爪维度 |
| 输出 | `[dx,dy,dz,rx,ry,rz]`，float32[6]，物理尺度增量 |
| 参考系 | 录包 `base_link`，尚未确认与真实控制基座的对应 |
| 锚点 | 决策参考点之前、已经接收的最新录制EEF位姿 |
| 平移 | 米，`p_future - p_current`，基座轴分量 |
| 旋转 | 弧度旋转向量，`Log(R_future R_current^T)`，基座轴分量 |
| 重建 | `p_target=p_current+dp`；`R_target=Exp(dr) R_current`，左乘 |
| 标签 | 未来录制状态变化代理；不是专家控制指令或已确认执行动作 |
| 四元数状态 | xyz位置＋xyzw；长度偏差≤1e-3才归一化；正w规范符号，pi处取最大xyz分量为正 |

`training.eef_action` 用纯NumPy实现四元数校验、旋转向量、位姿差分与目标重建。
不对欧拉角相减；不引用URDF、猜测TCP、翻转录包关节符号或调用IK。
当前位姿每步重新作为锚点，不能把增量连续累加到上一预测目标。
旋转取主值分支，跨pi时表示不连续；本轮短包未覆盖该姿态边界，不宣称全姿态连续编码。

## 时间与拒绝规则

沿用接收时间10 Hz参考网格；观测必须源header≤参考点，且在参考点前已经接收。
外部RGB、关节与触觉最长年龄250ms；EEF最长年龄50ms。
标签选源header≥参考点+100ms的第一条EEF，额外等待≤20ms；
从当前EEF锚点到未来EEF之间，源时间相邻间隔不能超过50ms。
不插值、不用未来图像或未来状态作输入，不通过放宽年龄补齐缺失观测。
保存reference、所有source、label以及`actual_horizon_ns=label-anchor`。
名义100ms从参考点计算，因此锚点到标签实际跨度不严格为100ms；bag_004为101.01～119.33ms。

错误frame、NaN、异常四元数、时间倒退、重复EEF源时间或header晚于接收会终止导出。
缺失/过期观测、缺未来标签、时间空洞、过大动作逐样本拒绝并计数。
试验边界为平移范数≤0.05m、旋转范数≤0.25rad；标签和候选超出时拒绝，不裁剪。
这些值写入契约及检查点；`check_increment`接收显式边界参数。
CLI第一版固定本契约，变更需新版本/重新导出和训练，不能运行时静默换尺度。
它们不是现场安全限位，没有速度/加速度、工作空间、碰撞或接触力执行器。

## 输入、数据与训练

外部RGB `(3,128,128)`、双指触觉 `(10,16,24)` 沿用旧BC预处理。
state为26维：左7关节、A/B各6维wrench、当前EEF xyz/xyzw。
v1不输入腕部；v2可选接入腕部，见下节。两版均不输入命令、夹爪或时间索引；腕部采集异常仍暂缓。
NPZ另含未来`target_pose`、动作标签与时间；它们只用于监督和审计，不传入网络。
未来位姿的发布者语义（反馈FK/目标FK）、真实TCP与单位/坐标仍需现场确认。

`eef_bc_policy` 为小型RGB CNN＋触觉CNN＋状态MLP，输出六维标准化增量；
反归一化后就是米/弧度增量，不再加当前关节位置。归一化统计只取训练episode。
一个bag暂算一个episode且成功状态未知；单包必须显式 `--overfit-smoke`。
独立验证按完整episode，拒绝重复episode和训练/验证交叉，不随机拆帧制造泛化结果。
支持 `--validation`，仍是小数据内存训练，无预训练、时序、动作chunk或SAC集成。

## 类型化候选与ROS验证

新增独立ROS接口包 `ros2/omi_action_msgs`，消息 `EefActionProposal`。
共享回放器 `bc_shadow --profile eef` 用localhost domain92及 `/omi/eef_shadow`；
旧 `--profile joint` 为默认，仍输出旧String JSON。
只发布11路观测及影子候选，不回放 `/tj/control/`。

`/omi/eef_shadow/policy_proposal` 包含参考时间、当前决策时间、EEF锚点时间、名义horizon、
epoch、动作版本、frame、单位、来源POLICY、代理标签语义、valid、shadow_only、
六维增量、锚点位姿与重建候选位姿。源参考时间是历史bag时间，decision为当前ROS时间，
两者不能直接相减解释真实控制延迟。当前只发有效候选，拒绝原因发到status，不伪造零动作。
消息预留rejection_reason；未实现人工输入、选定动作出口、HOLD/恢复自主状态机或执行器。
因此“类型化策略候选已实现”不代表整个接管方案已实现。

两个进程通过真实ROS订阅构造输入，源水位与输入SHA256保证与离线样本逐字节一致。
v2缓存只复制有效参考点选中的原始CDR消息，保留接收时间、源header和原始图像尺寸；
v1继续全量观测回放。v2未把PNG或预处理Tensor冒充原始消息，也不验证全量采集吞吐。
每轮begin清空有界历史；暂停检测STALE，无新参考不重复预测。
另建候选订阅检查CDR解码后的动作、目标位姿、单位与来源完全匹配；循环结束等待收齐。
验证时发现控制topic会失败，候选越界会拒绝并使完整预测数验收失败。
名义频率与水位握手属于离线回放协议，真设备独立调度/时钟同步尚未实现。

## 当前验证

bag_004：85参考点、70有效观测、69带未来标签样本；完整输入数量与拒绝原因存manifest。
500步CPU训练，同段平移分量RMSE 2.281→0.833mm，旋转向量分量RMSE 0.004278→0.001351rad。
零增量基线分别为2.293mm、0.004301rad；常量均值基线2.276mm、0.004272rad。
分量RMSE分别对N×3计算，不是三维距离RMSE或SO(3)测地角误差。
训练样本的最大增量范数19.06mm/0.02267rad，无边界拒绝。
数学重建残差平移0、旋转≤3.18e-17rad；它仅检验转换可逆，不能证明TCP校准。

两轮真实ROS验证140条、每轮70，全部输入一致；类型化候选140条实收且载荷一致。
同段指标与离线预测一致。第70条有效观测没有未来标签，允许预测、不参与标签误差。
旧record001关节BC回放复验109条，旧检查点可加载、输入一致、无控制topic。
首版完整测试147 passed、6 skipped；相机扩展后的最新证据见下节，ROS接口另有专项验证。
无GUI、Humble、真设备或闭环验收；不能据本段拟合宣称插孔成功或触觉贡献。

## v2：可选腕部相机与输入源标记

`export --wrist-camera {off,required,optional}` 选择 `bag-eef-bc-v2`；
不传该参数仍导出原v1，旧数据与权重继续可加载。实现位于`eef_bc_sources.py`，
每个profile持有自己的配置和缓冲，不修改全局旧契约。

| 模式 | 腕部输入规则 | 缺失/过期行为 |
| --- | --- | --- |
| off | 不读取或回放腕部topic | 全零图像，标记0 |
| required | 必须有≤250ms的因果腕部帧 | 拒绝整次观测 |
| optional | 有合格帧时使用 | 全零图像，标记0；其他必需源仍需有效 |

外部相机始终必需，源顺序固定为`[external,wrist]`。
`camera_mask: float32[B,2]`为输入源可用性标记，不是新的动作监督标签：
`[1,1]`用双相机，`[1,0]`只用外部相机。mask=1仅说明启用且收到符合时间/格式要求的图像，
不证明曝光更新、内容未冻结、图像质量或标定正确。缺失/过期不会伪装成有效黑图。

腕部从`/tj/dm_camera/camera/color`解码BGR→RGB，裁剪中心(.500,.704)、短边比例.36。
1920×1080取(766,566,389,389)，用最近邻缩到128×128，uint8按255归一化。
它与外部策略图像的尺寸、色序、缩放方式一致；人用腕部看板仍用Lanczos。
不改变ROI几何，不用看板PNG训练。

| 网络输入 | 批量shape |
| --- | --- |
| rgb：外部RGB | B×3×128×128 |
| wrist_rgb：腕部RGB | B×3×128×128 |
| tactile：双指数值场 | B×10×16×24 |
| state：关节、wrench、EEF | B×26 |
| camera_mask：输入源标记 | B×2 |

两个视觉编码器结构相同、参数独立，每路256维特征。
mask=0的腕部样本跳过编码器，特征为0，避免卷积bias混入；两个标记也直接拼入融合层。
optional训练按样本随机屏蔽20%的可用腕部输入，图像不进入编码、mask同步变0，
模拟缺相机；推理不随机屏蔽。required/off不做该增强。
这只提供缺失输入训练机制，不构成真实故障下控制性能保证。

数据、模型保存相同模式、topic、ROI、色序、resize、mask顺序和训练屏蔽概率。
训练/验证混合不同契约会拒绝；shadow在创建ROS节点前拒绝数据/检查点不匹配。
两个模式对同一原bag使用相同的基础观测episode指纹，不能因切换相机配置绕过重复数据检查。
同一个optional模型可以处理mask1或0，但不能把required模型静默改成optional。
任意新相机数量/顺序或替换外部源均需新profile，本次只配置腕部。

ROS水位同时包含腕部源时间（0代表未使用）；离线标记有腕部时必须等待对应帧，
不能因DDS迟到静默降级。离线标记没有腕部时保持0，不使用之后到达的帧改变同一决策。
输入哈希覆盖两幅图像、mask及原有字段；日志和报告保存每次mask。
动作消息结构仍是原6D候选，输入源配置保存在模型/报告，mask保存在预测JSON日志。
