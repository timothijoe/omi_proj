## 1. 旧BC究竟选择了哪个模型

此处“旧BC”特指`local/bc_episodes/bc_ready_20261007_01/actor.pt`的version295，
不泛指此前所有模型或异步RL权重。

- 源数据共8回合，但当时只用6回合944条训练，另2回合352条用于验证。
- 每轮计算验证集上的归一化动作MSE，保存误差最低的`actor.pt`。
- 训练到第13轮后早停，选中第5轮、295步的权重。推理不是加载最后一轮`last_actor.pt`。
- 选择发生在训练期间；推理只加载已选好的权重，并不现场根据验证误差选策略，也不使用验证数据代替实时观测。
- “验证最好”仅指动作预测MSE最低，**不是机器人任务成功率最高**；当时没有用实机成功率选模型。

最新8回合BC从上述295继续拟合，8回合1296条全部参与训练，已经没有独立验证集。
先4000步lr=1e-4，再从第一阶段最佳3750步权重出发，重建优化器细调8000步lr=1e-5；
按全部训练样本MSE选中累计追加11500步的模型，version11795。不是按验证误差选择。
异步RL又是另一种规则：每10个有效源回合检查最新有效checkpoint，并不宣称选的是“最优策略”。

## 2. BC到底训练了什么

“预训练视觉骨干”只是整个Encoder的一部分，不能与整个视觉分支或整个多模态Encoder混称。

| 部分 | 原BC295训练 | 全8回合BC训练 | 新保护式RL当前配置 |
|---|---|---|---|
| 下载的ResNet10视觉骨干 | 冻结 | 冻结 | 冻结 |
| 历史9帧输入卷积`history_stem` | 更新 | 更新 | 冻结 |
| 当前图像投影`current_projection` | 更新 | 更新 | 冻结 |
| 历史图像投影`history_projection` | 更新 | 更新 | 冻结 |
| 触觉编码器`touch` | 更新 | 更新 | 冻结 |
| 多模态融合`encoder.model.head` | 更新 | 更新 | 冻结 |
| Actor动作输出头`actor.head` | 更新动作均值 | 更新动作均值 | 前1000步不更新，之后带BC约束更新 |

触觉分支处理触觉网格，不是六维力/力矩；当前模型`wrench_history=false`。
BC监督信号为人工实际发送并被接受的归一化动作；误差反向传播到所有可训练分支，而非只训练最后一层。
确定性BC没有标定随机探索方差，不应将“Actor训练”理解为均值和探索分布均已可靠学好。

历史帧分支：9张RGB图像沿通道拼接为27通道，经过独立`history_stem`，再复用冻结的ResNet后续层，
最后经可训练历史投影层进入融合层。`history_stem`最初由下载骨干第一层权重重复9份并除以9初始化，
但它本身可训练。**用预训练权重初始化，不等于冻结权重。**
冻结的视觉骨干仍根据不同图片输出不同特征，不代表画面输入被忽略。

两次BC的冻结范围相同，最新训练没有额外“解冻触觉层”。中间单回合诊断确实做过
“冻结全部编码器、只训练Actor头”的对照，但不能混同为原BC295的训练设置。

## 3. 权重实测与效果解释

比较原BC295和最新BC11795，只统计相应模块的参数，指标为
`||W_new - W_old||₂ / ||W_old||₂ × 100%`。

| 模块 | 相对权重变化 |
|---|---:|
| 预训练视觉骨干 | 0% |
| 历史帧输入层 | 19.2737% |
| 当前视觉投影 | 5.9870% |
| 历史视觉投影 | 3.7562% |
| 触觉编码器 | 10.3062% |
| 多模态融合层 | 32.9179% |
| Actor头（供参考） | 5.3668% |

这些不是性能提升百分比，不同模块的相对变化也不能直接作为重要性排序。归一化缓冲量未变化。
另直接比较`local/pretrained/serl_resnet10/backbone.pt`与BC11795的骨干：
下载文件SHA256与recipe记录一致，38个权重/缓冲张量逐项相等；确实保持下载版本不变。

全部8回合上的动作MSE由0.0462581降到0.00088644，明确dx标签符号一致率95.81%→100%；
433条全零标签上，每条最大预测分量绝对值的均值0.31522→0.04361。
用户反馈最新模型“有那个感觉”，不是正式成功率结果。
更充分训练、低学习率细调和额外纳入2回合共同改变了结果，不能单独归因于其中一项。
也不能由训练集拟合改善推断验证选择必然错误、原模型完全没学到、或最新模型能泛化到新起点。

## 4. 最新已实现的三项RL开发

### 周期采集转训练数据

主线程按100ms目标发命令，不等待每条回执；写盘线程记录`periodic_episodes/`，回合结束后后台校验。
检查命令来源/ID、动作与SDK转换一致性、接受时间、完整前后观测，以及命令接受之后确实收到后继EEF。
观测间隔要求80–150ms，接受延迟不超过50ms；RB打断、回执/观测缺失、拒绝或明显断档排除对应区间。
连续有效段导出到`episodes/<源回合>-segment-*/ready.json`，Learner独立导入磁盘replay。
不跨断档拼接；断档段以truncated收尾，保留bootstrap。动作语义是accepted_command，不是实测位移。

成功停止后、人工复位前可抓取第一个完整终止观测，要求EEF已更新，记录`terminal_success_stop_ns`。
该动作可能因成功停止而缩短，不能宣称完成了完整名义位移；成功终止不bootstrap。
只有合格末段才记录成功奖励，末段不合格则`success_label_recorded=false`，不把早先动作补标成功。
异常/Ctrl+C中断源回合仅保留审计。普通BC入口仍audit-only，旧审计数据不自动回填。
按源回合计数：一个完整源回合即使导出多段也只计一次；无合格段不计入10回合换权重门槛。

### BC初始化完整RL

新增`scripts/prepare_bc_rl.sh`和`hil/prepare_bc_rl.py`，仅允许新目标目录。
校验BC契约、原数据哈希和动作标签，复制全部Actor/共享Encoder/归一化；初始化新Critic头、
同步target，并建立新的优化器。最后写会话标记，未完成初始化的目录不能启动。
已准备`local/rl_training/bc_protected_20261007_01`，8回合1296条，容量4000。
历史人工样本当前同时计入online与demonstration流，不能把这个计数当作新增机器人经验。
会话标记`control_mode=periodic_training_v1`选择新路径，旧RL会话和原BC入口不变。

### Critic预热和BC保护

整个共享Encoder保持冻结；前1000个Learner更新只训练Critic头，Actor和温度不更新。
之后每2步Critic更新进行1步Actor更新，Actor lr=1e-5，SAC目标加10倍human动作标签MSE。
保存固定BC参考，记录`bc_loss`、`bc_reference_mse`和`bc_reference_max_abs`。
checkpoint保存冻结配置、参考BC、计数和优化器状态，恢复不重新开始预热。

**1000步后编码器仍冻结，没有自动解冻。** 后续可以考虑继续冻结骨干、以约1e-6微调触觉/融合/
视觉适配层，并让BC约束保护共享编码器；这只是讨论建议，尚未实现或验证，不是当前行为。
当前漂移指标不触发自动回滚，Actor仍确定性推理，尚无新增交互量对应的更新预算。
