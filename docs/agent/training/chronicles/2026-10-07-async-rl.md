## 当前主入口与一键启动范围（补充交接）

当前推荐的是异步入口，不再用交替入口作为默认现场训练流程。
`run_alternating_rl.sh` 保留用于已有实验，但不要和异步入口在同一目录或控制topic并行运行。

```bash
bash scripts/run_async_rl.sh \
  --run local/rl_training/async_20261007_01 \
  --reload-every-episodes 10 \
  --batch-size 2 --publish-every 50 \
  --execute
```

一个终端、一条命令：父进程同时承载Actor/手柄/回合采集，并自动启动独立Learner子进程。
不是需要分别手动启动，也不是已实现多机分布式部署。写盘和权重加载各有后台线程。
训练子进程输出到运行目录 `learner.log`。实时推理仍在Actor主线程，RB不是硬实时急停保证。

上面命令默认人工操作+后台RL训练；只有显式加 `--enable-policy`，ACTIVE内松开RB才执行模型。
传感器服务与机器人控制接收端必须提前独立运行；本入口不启动这些外部服务。
不要另外启动手柄或模型动作发布脚本，以免争用控制topic。

按键315开始、308成功结束、307未成功提前结束；超时继承本目录15秒契约。
每个完整有效回合都提交入池，10回合只是Actor刷新频率，不是积攒10回合才训练。
默认训练门槛为在线流100条、人工流1条；现有seed两流各929条，所以立即满足门槛。
Learner不受回合次数限制，没有新数据也继续训练已有replay。
`--publish-every 50` 按本项目Critic更新次数计数，不等于官方HIL-SERL外层循环50步。
每10回合只检查最新完整有效权重，不等待新版本，不以训练loss认定“最优”。

## 用户确认的退出行为

在启动终端按一次Ctrl+C，关闭本次采集、手柄读取、Actor发布者、写盘任务及Learner子进程。
完整回合保留；被打断的未完成回合仅留审计，不作为训练样本。
通知Learner在当前完整更新结束后保存，默认等待30秒；超时强制回收并明确提示检查恢复状态。
不是瞬时退出；模型加载/磁盘保存也可能需要等待。重复Ctrl+C不打断清理。
独立启动的摄像头/触觉服务、机器人接收端和RViz不在关闭范围；Ctrl+C不能代替硬件急停。
干净退出后可原命令重启；dirty replay/强杀恢复仍需检查，不承诺任意中断无损续训。

- 训练预算：没有新增数据条数与更新次数的比例限制；只增加了可选update-delay用于资源节流。
- “最优模型”选取：没有真机独立评估/排名，因此只有最新有效版本。

  不能宣称“等超时自然会把value判低”，也不能把307当作已实现的负奖励按钮。
