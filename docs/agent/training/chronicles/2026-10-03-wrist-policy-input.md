# 2026-10-03：腕部策略输入与相机可用性标记

## 目标与实现

用户要求加入腕部相机，尺寸与现有视觉输入相同，并提供决定是否使用腕部的label/机制。
本轮将其实现为显式输入源配置及每次观测的camera_mask，不改变动作监督标签。

新增`bag-eef-bc-v2`：外部/腕部各3×128×128 RGB、camera_mask float32[2]，
触觉10×16×24、状态26、动作6保持。off/required/optional配置随数据和checkpoint保存，
影子推理拒绝不匹配版本。无参数导出继续旧EEF v1，七关节BC不变。

腕部解码BGR→RGB，复用(.500,.704,.36)ROI，最近邻128，与训练/推理一致；看板Lanczos不改。
两路独立视觉编码器；无效腕部样本跳过编码器、特征置0，标记直接参与融合。
optional训练按样本随机屏蔽20%可用腕部，推理不随机屏蔽。
缺失/过期可以标0；错误图像格式和倒退时间仍报错，不把损坏数据伪装成正常缺失。

## 原包导出与真实训练

继续使用同一bag_004（来源SHA256见前篇末端动作编年）。
开启、关闭各69带标签样本、70有效观测；外部/触觉/状态/动作与原EEF版保持，追加腕部/标记。
optional训练500步约3.81秒，同段平移分量RMSE约0.746mm、旋转分量0.001415rad；
off训练500步约2.59秒，同段0.842mm、0.001629rad。
两模型都只做单包过拟合，随机屏蔽与融合结构也有区别，不能凭这两个指标认定腕部贡献。

## 全量回放失败与修正

初次optional全量原图回放仅11/140预测，121次等待超时、8次过期参考拒绝，验收失败。
结果符合全量大图和高频状态消息导致的订阅/历史积压；未单独测量DDS、解码和历史覆盖各自的占比。
随后off全量回放在并行验证负载下也只完成105/140；未将这些报告称为通过。

v2导出改为仅复制有效参考点实际选择的原始CDR帧；参考点、水位、原始像素、header及
原接收时间均保持，不改采集器、原包或旧v1行为。源345条腕部取63条、5219条EEF取70条，
重复使用同一源帧只发送一次。源消息数量与回放数量分别写报告。
选帧前后optional的samples.npz SHA256相同：
`fd81618191ee61f2bec602deff14484e79ba964302df5472491da0fbfe3f2771`。
该修正用于验证10Hz策略输入，不宣称完整高分辨率采集流已满足实时吞吐。
