## 可复现的接收端缺陷与修复

切换时 Actor 向两个通道发送停止零动作，再向选定通道发送动作。
跨 topic 不保证到达顺序：旧通道的无 ID 零动作可以晚于新通道的动作到达。
旧接收端此时会重置当前来源、停止新通道并错误取消新命令的回执。
离线测试在 policy→human、human→policy 两个方向均复现，修复后通过。

现在无 ID 的零停止只作用于自己的通道，不影响另一通道正在执行的命令及回执。
带 HIL 命令 ID 的零动作是明确选中的动作，仍可切换来源并停止运动，例如 RB 按住且摇杆回中。
这修复了一个确定的切换缺陷，但没有证明它是本次持续“抢控制”体感的全部原因。
SDK/阻抗控制仍从最近下发目标继续积分，实际目标与反馈偏差需要新诊断核对；本次未改变执行锚点。
