# 2026-10-09：观测驱动动作与时序仅诊断

## 用户决定

主要维护 `collect_rl_episodes.sh`（人工示范，供 BC 与 RL 使用）和 `run_async_rl.sh`（真机在线 RL）。
其他控制入口不删除，按需维护。用户明确选择保留 10 Hz observation 节拍，到点取各路 latest，
不刻意等待某一路；动作随观测触发，推理完成即发送。推理超时与因果时序检查只日志，
不作为动作阻断、训练入池排除或策略效果不正确的判据。

## 实现

- `run_periodic` 移除独立动作定时器。人工动作在新观测处读取；策略由后台推理完成后发送。
  接收端零动作握手仍先于正式命令。
- latest 观测读取各路最后一份有效数值，包括参考时刻之后刚收到的数据；header/接收年龄只诊断，
  不清除缓存。未收到必需字段、格式错误或非有限值仍不能构造输入。历史不足保留真实 mask 和零占位。
- 推理忙时只保留最新待处理输入，已完成结果连同实际输入快照交付一次后再计算下一份输入。
  超过 100 ms 打印 `ACTION_TIMING`，不因此丢弃、改零或重发旧动作。
- RB、停止和断连仍取消旧候选；RB 释放后从下一份观测恢复策略。只有尚未收到回执的已发送命令
  参与失联检查，空闲等待推理不触发该故障。
- 新周期记录标记 `timing_policy=diagnostic_only_v1`。Replay 导出和 BC 标签读取同步适配，
  EEF 因果、发送相位、回执延迟、间隔与接管时序只进入诊断，不据此切段或丢样本。
  命令身份/单位/来源、已接受回执、数组形状与数值仍核对，实际拒绝/缺失证据不会伪造为已接受动作。
- `observations/<reference_ns>.npz` 独立记录每个实际观测节拍及源时间，包括没有动作的观测和停止后排空期间的观测。
  原目录数字文件保存每条已发送命令及其实际输入，`timing_diagnostics.json` 保存逐条时序诊断。
- 新人工会话默认 periodic；恢复时未指定模式则沿用旧会话 receipt/periodic。当前 BC 热启动异步会话
  `periodic_training_v1` 分派到新循环。固定 BC 的 periodic 共用新循环，旧 receipt 与旧连续推理保持兼容。
- 监控及逐帧查看明确将新时序告警标为诊断，不直接等同数据排除或输入拒绝。

## 数据解释

标签仍是已接受的归一化命令，不是实测位移。训练对沿相邻动作的输入快照配对，末步使用停止附近的后续观测，
不为未推理的观测伪造动作。慢推理时观测间隔可超过 100 ms，下一输入也可能早于上一命令发送；
真实时间与诊断保留。当前 SAC 折扣、动作尺度与更新预算不变，不声称这些数据保证物理因果。

本次不重处理历史 1959 tick，也不将历史排除的 900 tick 自动补入 Replay；已有模型、池和示范未改写。
接收端速度保持及 0.25 秒断流停止未修改：慢推理可能导致接收端停止保持，但 Actor 不因推理超时丢弃结果。

## 验证与生效

离线测试覆盖 latest 旧/未来 header 与旧接收帧、部分历史立即可用、推理结果不被覆盖、等待区只留最新、
RB 取消/恢复、模拟 1.3 秒推理期间持续记录观测并正常发送结果，以及时序异常数据通过 BC 核对和 Replay 导入。
同时回归旧严格数据、固定 BC、异步 Actor/Learner、保存退出、Start 历史保留与监控 HTTP。

最终相关测试合计 **169 通过、3 跳过**。主回归在 `.venv` 关闭 pytest 自动插件加载后运行；
其中两项旧 wrench 兼容测试因该环境缺少 SciPy，随后追加本机
`local/resnet10-validation-env/lib/python3.12/site-packages` 到测试进程的搜索路径，
确认 SciPy 1.18.1 / NumPy 2.5.3 可用后补测通过；未安装或替换环境依赖。
另通过两个主入口的 `--help`、JavaScript 语法、Python 语法及 `git diff --check` 检查。

没有连接设备、发布机器人动作、重训现有模型或重启现场程序。操作者正常退出并等待保存后，
按原命令重启即可使用新周期逻辑。真机并发时延、磁盘写入负载与任务效果仍待现场观察。
