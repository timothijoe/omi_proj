## 需要讨论的问题

1. 两指wrench在10个包中均为0条消息。新版state只保留7关节＋7位姿，共14维；不伪造12维零力值。
2. 触觉header通常比接收时间快约28–32ms，腕部约20–24ms，跨设备时钟未校准。
   新版统一按录包接收时间选择观测与未来EEF代理标签，保留原header，不估计/修改时钟偏移。
   这保证接收层面的因果关系，但不保证曝光/接触时刻严格同步；源时间新鲜度与接收时间新鲜度不同。
3. bag_003/005/007/008各有一条外部相机旧帧，header比接收时间早约25.82/11.03/9.37/26.85秒。
   它们已从有效输入剔除。其他延迟异常同样按入口规则剔除，共42条源消息。
4. bag_009原始EEF最大header间断233.70ms；入口过滤后接收时间间断345.92ms。
   该包仅保留71/100样本；有效标签不跨越超过50ms的EEF间断。本轮该时间段主要先被RGB缺失检查拒绝，
   因此最终drop统计中没有独立的eef_time_gap计数，不代表没有间断。
5. 腕部每包存在重复像素帧（约16%），但并非整段相同；抽帧可见场景与夹持物。
   尚未人工逐段标注成功/失败、任务起止或夹爪事件，不能将重复帧直接解释为故障。
6. 保留以前的6D末端动作，不训练夹爪；即使包里有gripperValueL，也没有加入标签。

## 转换后的格式

版本：`bag-eef-bc-v3-grid-receive`；与旧v1/v2不混用数据或检查点。
每包在 `datasets/bag_NNN/`，包含 `samples.npz`、`manifest.json`、`references.json`、`observations/`。

| 数组 | 每样本shape | 含义 |
|---|---|---|
| rgb | 3×128×128 uint8 | 外部相机，沿用旧ROI与resize |
| wrist_rgb | 3×128×128 uint8 | 录包已经裁剪，只做BGR→RGB，不二次裁剪 |
| camera_mask | 2 float32 | 外部/腕部可用标记；1525个样本均为[1,1] |
| tactile | 10×16×24 float32 | 双指各def_xy、shear_xy、depth；不重复池化 |
| state | 14 float32 | 左臂7关节＋EEF xyz/xyzw |
| action | 6 float32 | 约100ms后录制EEF变化，米/弧度旋转向量 |

另含reference_ns、source_ns、label_ns、original_source_ns、original_label_ns、actual_horizon_ns、target_pose。
source/label_ns属于录包接收时钟；original_*保留原设备header。
入口拒绝接收−header超过250ms的普通观测、超过50ms的EEF，或header超前接收100ms以上的消息。
这些是本次数据筛选阈值，不是时钟校准、硬件安全限位或实时保证。
观测在10Hz参考点前已接收；EEF最长年龄50ms，其余250ms；标签在参考点后100–120ms。
所有数组哈希/形状/有限值、因果时间、位姿重建通过验证。
observations只复制被选中的原始CDR帧；新版ROS在线影子入口明确拒绝，尚未实现接收时钟在线适配。
